## 1. 被推翻的判断：向量不是空白

我第一、二、三批都写"公开一致性向量是行业空白"。实况：

> `aip-protocol` 的 `conformance/run_conformance.py` 自述：*"This runner is the authoritative proof that the SDK implements AIP-1 correctly. For other language implementations: load vectors.json … Run verify_intent() … Assert the expected results."*
> 而且 `generate_vectors.py` 明写：*"Any AIP-1 implementation in any language must produce the same results for these vectors."*

**他们也在做语言中立向量。** 所以护城河 A 从"空白"降为"形态不同"。

差别在哪（这是唯一还剩下的地方）：

| 维度 | aip-protocol 0.4.0 | 我们的 repro_kit |
|---|---|---|
| 向量生成方式 | **用自家 SDK 的 `_get_signable_payload()` 生成**（自引用：实现定义规范） | 由独立规则表人工定义，两套实现各自去适配 |
| 依赖 | 需 `cryptography` + pydantic 模型 | **零依赖**（标准库 / Node 内置） |
| 语言覆盖 | Python SDK + 声称"任何语言可跑" | 已实跑 Python + Node，**跨语言 diff = 0** |
| 覆盖域 | 信封/签名/nonce/额度/地理/分层/Kill switch（八类） | 生命周期 / 护照交换 / 规范化攻击 / 版本协商 / 多源撤销 / 时钟偏斜 |
| 撤销侧 | 只看"是否被撤销" | **链式只增 + 单调序号 + 快照时效 + fail-closed** |

**诚实的结论**：我们的向量不是"独有"，而是"**规则表驱动的、零依赖的、覆盖撤销语义的**"。这是一个真实但更窄的差异。

## 2. 用他们的真实代码暴露的四个缺口（P15–P21）

| 用例 | 事实 | 证据 |
|---|---|---|
| P19 | `reinstate()` **直接删除记录**，撤销历史被抹掉 | `revocation.py:172-179`，调用后 `len(_revocations)==0` |
| P20 | 无历史证明 → 本 profile strict 一律 `DENY:no_history_proof` | 实跑 |
| P21 | `RevocationStore` / `RevocationRecord` **没有单调序号字段** → 无法检测旧快照重放 | `hasattr` 实测 False |
| P17 | 暂停过期后 `is_revoked()` 自己返回 False（fail-open），状态无留痕 | 负时长暂停实测 |

这四条不是"他们做得差"，而是**他们选择了 in-memory + DB 持久化的路线，本来就不打算做密码学历史证明**。所以我们不该说"他们不安全"，只能说"**我们的判定在他们的产物上会拒绝**"——这是立场差异，不是优劣。
