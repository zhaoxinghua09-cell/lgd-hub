# XLGD 竞品格局与"断崖式领先"打法（2026-11-19）

**性质**：只读调研 + 战略设计。未对外发布、未接洽竞品、未提交标准。
**标注**：FACT / INFERENCE / NOT VERIFIED

---

## 0. 先说结论

"全面超越竞品"在 12 个维度里今天做不到——**我们领先 5 项、持平 1 项、落后 6 项**。

但"断崖式领先"是另一回事：**不是每条都第一，而是某几条窄道上别人短期抄不走**。

可抄不走的只有三条，而且都建立在同一个东西上——**可验证性**：

1. **公开一致性向量 + 复现包**（行业空白：草案没有 conformance vectors，商业产品不出 repro kit）
2. **跨域撤销传播规范**（行业公认未解：支付网络只在自己域内做 registry）
3. **供应商无关的离线永验**（竞品的"证明"随服务下线一起消失）

## 3. "断崖式领先"到底是什么

### 3.1 不是"全面第一"

在 #1/#2/#3 这三项上，Okta/Microsoft/Zenity 已经 GA 且有客户。我们落后不是 1 年，是**一个产品化周期**。任何"全面超越"的说法都会在第一次客户尽调时崩掉。

### 3.2 是"三个窄道上无人替代"

| 护城河 | 为什么别人短期抄不走 | 我们的存量 |
|---|---|---|
| **A. 公开一致性向量 + 复现包** | 商业产品没有动力公开（暴露误报）；标准草案通常只写需求不出向量；这需要"愿意被人跑"的姿态 | 30 条向量 + `run.py` / `run.mjs` 双语言实现 + 回传 schema |
| **B. 跨域撤销传播** | 涉及多家厂商协同，谁都想当注册中心；支付网络已有域内方案，没有动力扩展 | GTP-1 的 `gtp-rev/1`：serial 单调、`next_expected_by`、只增不删、三种快照获取 |
| **C. 供应商无关离线永验** | 与"平台锁定"直接冲突——这是商业模式的取舍，不是能力问题 | `verify` 离线跑（FACT）；OTS/RFC3161/Rekor 锚；证据可导出 |

**三条合起来是一句话**：**别人证明"我信任你"，我们证明"这件事可以被任何人独立验证，而且我不在了也能验"。**

### 3.3 时间窗

**12 个月内有效**。理由：
- 一旦某个大厂（Okta/Google）发布 conformance vectors，A 立刻归零
- 一旦 IETF 出现 revision feed 草案，B 变成"参与"而不是"首创"
- 一旦客户接受"平台内审计够了"，C 的价值会被低估

所以打法必须是**快发布、先占位、再接入**。

## 4. 九十天打法（三阶段）

### 4.1 第一阶段（0–30 天）：把存量变成公共品

| 动作 | 产出 | 验收 |
|---|---|---|
| 发布 GTP-1 草案（CC-BY） | `specs/GTP-1.md` + 20 向量 | 外部人 30 分钟能跑通 |
| 发 `gtp-rev/1` 撤销 feed 规范 | 同上 §5 | serial 单调/时效/只增不删三条可测 |
| 向量已扩到 30（补：规范化攻击 5 条、版本协商 2 条、多撤销源 2 条、时钟偏斜 1 条） | `vectors.json` 30 条 | Python 30/30、Node 30/30、跨语言 diff 0 |
| **把"我们落后 6 项"写进对外定位页** | 一页定位 | 不夸大 |

**这一阶段的关键不是写更多，是把已有 20 条变成别人能引用的东西。**

### 4.2 第二阶段（31–60 天）：接入而不是发明

| 动作 | 说明 |
|---|---|
| AAP claims 映射表 | `agent.id` / `task.purpose` / 委托链 → GTP-1 的 identity/authorization 扩展 |
| AAuth per-instance 身份对接 | `key_fp` 直接取 HTTP Message Signatures 的密钥指纹 |
| Web Bot Auth 组合 | bundle 作为签名之外的证据层，不替换它 |
| Verifiable Intent / AP2 映射 | 支付域 evaluation 标注 `domain: commerce` |
| 第二个实现 | 邀请 1 名非关联开发者按规范实现（**需批准**） |

**原则：不新造身份体系。** 我们已经在 IETF 草案里看到明确方向（复用 WISME/OAuth），逆着走没有意义。

### 4.3 第三阶段（61–90 天）：拿证据说话

| 动作 | 验收 |
|---|---|
| 双实现一致性报告 | 同一 30 向量，两实现结果 diff 公开 |
| 撤销传播实测 | 两实现 + 一个 feed，测传播时延（目标 ≤5 秒） |
| 首个付费试点 | 1 家（**需批准**） |
| 一篇方法论文（可投 IETF/学术） | 只投稿，不代表采纳（**需批准**） |

## 5. 明确不做的事

| 不做 | 理由 |
|---|---|
| 不做 Agent 身份目录 | Okta 已 2 万客户，做就是烧钱陪跑 |
| 不做影子 Agent 发现 | 需要端点/网络权限，我们没有任何部署基础 |
| 不做运行时网关产品 | Zenity/OpenBox/Lyzr 已 inline；我们连 PEP 都没有，先补 PEP 再谈产品 |
| 不做支付认证 | Visa/Mastercard/Amex 已有认证体系与生产交易，进入门槛是牌照级 |
| 不宣称"认证" | 商标未注册、无认证计划（前轮已确认 `entity_or_trademark_registered: false`） |

## 6. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 大厂先发 conformance vectors | 护城河 A 归零 | 30 天内发布，抢时间戳（OTS 锚定发布件） |
| IETF 出现 revocation feed 草案 | 从"首创"降为"参与" | 提前把 GTP-1 投到相关 WG（需批准） |
| 20 条向量被认为太薄 | 不被引用 | 90 天内扩到 30 条 + 双实现报告 |
| "断崖式领先"被理解为全面领先 | 尽调时信誉受损 | 对外材料必须写"5 领先 / 6 落后" |

这不是退而求其次，这是唯一在 12 维矩阵里我们能长期占住的格子。
