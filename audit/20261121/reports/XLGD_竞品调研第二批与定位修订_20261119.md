## 0. 必须先修正的一句

**第二批调研推翻了后半句**：

**所以：我们不做第二个扫描器。** 见 §4 的新定位。

## 2. Web Bot Auth：证明了我的论点，也证明了我的空白

读了 `draft-meunier-webbotauth-httpsig-protocol-02` 与 IETF 126 的 slides [4][5]：

- 机制：RFC 9421 HTTP Message Signatures，`Signature-Agent` 头做密钥发现，`.well-known/http-message-signatures-directory` 发 JWKS（Ed25519）。
- **两种绑定模式**：opaque（锚在密钥，换钥即换身份）vs domain binding（锚在域名，走 WebPKI + TLS + 目录签名）。
- 草案明写：**"The protocol anchors on the key. The directory is optional and adds the domain."**
- 草案明写：**"Signature-Agent provides key material. It does not confer trust."**
- 现行部署**fail-open**：签名有效可免挑战，未签名仍放行（只是被 challenge）[6]。

**这两句直接确认了我们的位置**：Web Bot Auth 明确把"密钥材料"和"信任"切开——**它自己声明了它不解决信任**。这正是 GTP-1 的 `evidence`/`evaluation`/`authorization` 三段要填的洞。

**但也要承认**：Web Bot Auth 已有 Cloudflare/GoDaddy/Google/AWS 的真实部署，我们一行部署都没有。

## 3. AP2：生态已成规模，且已有人在抢"治理层"

- AP2 核心是三类 VDC：**IntentMandate**（人在不在场都适用的长期授权）、**CartMandate**（人在场时的执行授权）、**PaymentMandate**（支付工具授权）；分 **open / closed** 两态，closed 靠 Key Binding JWT（PoP）绑定到具体交易；`delegate_payload` 用 SD-JWT [7][8]。
- 发布方：Google + **60+ 支持方**（PayPal、Mastercard、Visa、Adyen…）。
- 关键一句：**"Verifiable Intent, Not Inferred Action"**——与我们的"证据可复算"同源。
- **但** AGP（BIAN 生态）公开指出：**AP2 V0.1 没有定义治理证据的标准头**，`X-AGP-Action-ID` 只是其私有约定；他们正在用 capability token / action envelope / immutable ledger 去补 [9]。

**判断**：支付域正在出现"治理层"的竞争者（AGP/BIAN）。我们的 GTP-1 如果只做通用域，会与 AGP 在支付域重叠；**应当明确声明"不进入支付域，只提供跨域验证"**，否则会被当成第三方方案。

## 4. 定位修订：从"扫描者"改为"验证者"

### 4.1 修订后的矩阵增量（新增 3 维）

| 新维度 | 阿里云 | 奇安信 | 蚂蚁 | XLGD |
|---|---|---|---|---|
| Skill 静态/动态安全检测商业化 | ✅ 2026-09 | ✅ | — | ❌ |
| MCP 调用身份与最小权限 | ✅ Agent ID Guard | ✅ | 部分 | ❌ |
| 跨机构 KYA 协同框架 | — | — | ✅ 与卡组织/Swift 共建 | ❌ |
| **对他人扫描结果的独立复算** | ❌ | ❌ | ❌ | **✅ 唯一可做** |

### 4.2 结论：领先维度从 5 收窄到 4

仍然成立的四条（全部是"验证"而非"检测"）：

1. 公开一致性向量 + 双语言实现（30 条）
2. 跨域撤销 feed（`gtp-rev/1`，已实现 15/15）
3. 供应商无关离线永验
4. 评测 ≠ 授权的强制语义（score 单独绝不授权）

**不再成立**：把"Skill 扫描/静默失败目录"当作差异化——阿里云已商业化，我们只有 9 条语料。

### 4.3 新打法（一句话）

> 不跟阿里云比"扫得准"，而是让**任何一家扫出来的报告都能被别人独立复算**。

具体形态：GTP-1 的 `evaluation` 段增加 `evaluator`（谁扫的）+ `report_digest`（报告哈希）+ `corpus_version`，使阿里云/奇安信/OpenBox 的报告都能被第三方重算一致性。我们不评价他们准不准，只保证"这份报告没有被改过、且规则版本可追溯"。

这条路的商业含义：**成为别人的验证层，而不是别人的竞品**。这也正好绕开"没有客户基础"的死结——我们不需要自己的客户，只需要别人的报告。

---

## 5. 窗口修订：12 个月 → **6–9 个月**

缩短的理由（FACT 支撑）：
- 国内三家已在 2026 年 Q2–Q3 完成商业化落地；
- 阿里云已具备 Skills 检测 + 运行时防御 + MCP 身份，**下一步必然是"结果可信"**；
- 蚂蚁已在与卡组织/Swift 共建跨机构 KYA——这正是"跨域撤销/信任传播"的商业化路径。

所以：**规范必须在这半年内被至少一个外部方引用，否则会从"首创"变成"重复造轮子"**。
