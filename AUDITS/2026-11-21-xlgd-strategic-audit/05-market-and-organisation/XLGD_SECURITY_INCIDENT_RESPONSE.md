## 一、九类事件 × 定义

| E2 | Critical 漏洞（工具自身） | SAST/外部报告 | P0 | 停用相关命令/加警示 | 内部 + 使用者 | 补丁 + 回归 | 协调披露（CVD） |

## 二、六个阶段（每类都走同一流程）

```
Detect → Severity → Contain → Impact → Notify → Remediate → Re-verify → Close → Disclose
```

| 阶段 | 时限（建议） | 责任人 |
|---|---|---|
| Detect | 24h（由巡检发现） | AI 巡检 |
| Contain | 4h（P0） | Steven 批准后执行 |
| Impact | 24h | AI 起草，Steven 定稿 |
| Notify | 客户 24h；公众按披露策略 | **Steven** |
| Remediate | 3–7 天 | Steven/AI |
| Re-verify | 修复后 24h | AI 跑固定样本 |
| Close | 复验通过 | Steven |
| Disclose | 按策略 | **Steven** |

## 四、披露政策（三条）

1. **默认披露自己的错**（False PASS / 未审批发布），因为信任来自"承认失败"；
2. **默认不披露**他人未修漏洞细节、客户数据、密钥信息；
3. **协调披露**（CVD）用于第三方产品漏洞：先私下通知，90 天后公开。
