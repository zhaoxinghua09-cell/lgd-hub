# PRICING_AND_UNIT_ECONOMICS（定价与单位经济模型 · 2026-11-21）

> 铁律：**没有任何客户验证时，不得把任何价格写成"市场价"。** 本文件把所有数字明确标成四类：①已有真实价格证据 ②竞品公开定价 ③市场推测 ④我们自己的测试价。

## 一、四类价格证据的现状

| 类别 | 现状 | 说明 |
|---|---|---|
| ① 真实成交价 | **0 条** | 无订单、无报价、无发票 |
| ② 竞品公开定价 | **未取得** | 检索到的商业平台（BetterClaw、LikeClaw、Microsoft AGT）**未公开价目**；不得编造 |
| ③ 市场推测 | 可用但不可外发 | 审计服务通常按"人日"计价（I） |
| ④ 自测价 | 可给（内部） | 见 §四，标注"测试价，未经客户验证" |

## 二、八种计价方式 × 适配度

| 方式 | 适配 | 理由 |
|---|---|---|
| 按次评测 | **最适合** | 交付物是报告，边界清楚 |
| 按 Agent 数量 | 中 | 客户易理解，但我们按对象计价更公平 |
| 按 Skill/MCP 数量 | 中 | 适合批量扫描（未来） |
| 按 API 调用 | **不适合** | 分数 EXPERIMENTAL，按调用收费会放大误判 |
| 年度订阅 | 未来 | 需先有 monitoring 与 SLA |
| 按审计项目 | **适合**（大客户） | 与咨询机构分成模式契合 |
| 持续监控 | 未来（30 天后） | 需先建 monitoring |
| 整改复测 | **适合** | 天然的第二笔收入（同一对象） |

## 三、单位经济（单次 MCP Trust Audit）

| 项 | 估算 | 依据 |
|---|---|---|
| 人工交付 | **8–16 小时**（首单 16，熟练后 8） | 本机实测：扫描 5 分钟，人工整理与复核占 80% |
| 云资源 | ≈0（本地跑） | 只读、无 GPU |
| 测试维护 | 每月 2–4 小时 | 规则变动 + 样本回归 |
| 客户支持 | 首单 2–3 小时 | 解释"能/不能验"耗时最多 |
| 客户获取成本 | **未知（最高不确定项）** | 无渠道数据 |
| 毛利空间 | 人工为主 → 毛利率取决于时价；规模化后下降不明显（**瓶颈是人**） | — |
| 续费可能 | 中（版本变更触发重评） | 51.1%/40.6% 漂移数据支持 |
| 规模化能力 | **弱**（单人） | 必须先有模板 + 外部交付伙伴 |

**关键结论**：这是一个**人力生意**，不是软件生意。若要规模化，只有两条路：①模板化到 2 小时/单；②授权咨询机构代交付（分成）。

## 四、自测价（内部测算，非成交价，禁止外发为"市场价"）

| 方案 | 价格 | 说明 |
|---|---|---|
| 试点价 | 成本线附近（覆盖 8–16 h） | 用于换取案例与反馈，可标"试点" |
| 标准价 | 成本 × 1.5–2.5 | 需在试点后按实际耗时校准 |
| 复测价 | 标准价的 40–60% | 同一对象、仅版本变更 |

> 具体金额由 Steven 决定；本文件**故意不给数字**，以免被引用为"官方定价"。若需数字，用公式：`价格 = 人工小时 × 时价 × 系数`。

## 五、三条定价红线

1. **不承诺 SLA、不承诺"认证"**（无资质、单人）；
2. **不按"分数"计价**（分数 EXPERIMENTAL，按分数收费等于卖不确定）；
3. **不设"包通过"**（任何"保证过审"都违反本生态的诚实原则）。

## 六、90 天内要验证的三个价格假设

| 假设 | 验证方式 | 失败即 |
|---|---|---|
| H1：客户愿为"一页结论 + 证据包"付费 | 首单试点 | 转为免费引流 + 咨询分成 |
| H2：复测可单独收费 | 第二次交付报价 | 只做一次性 |
| H3：咨询机构愿分成代交付 | 一次合作洽谈 | 保持直销 |

> 诚实条款：本文件除"人工 8–16 小时"来自本机实测流程外，其余均为判断（I）。
