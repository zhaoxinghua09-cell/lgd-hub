## 1. 交付物一：Trust Lifecycle Architecture

### 1.1 十三态状态模型（合并原 7 态 + 6 异常态）

```
REGISTERED → EVIDENCE_PENDING → VERIFIED → EVALUATED
           → AUTHORIZATION_PENDING → AUTHORIZED → MONITORED
异常：UNKNOWN / INCOMPLETE / EXPIRED / REVOKED / SUSPENDED / FAILED
```

### 1.2 每条边的触发条件（这是关键，状态机不能只有箭头）

| 转换 | 必需证据 | 必需规则 | 附加条件 |
|---|---|---|---|
| REGISTERED→EVIDENCE_PENDING | 注册记录 | — | — |
| EVIDENCE_PENDING→VERIFIED | 证据摘要 + 签名 | `rule_id` | 验签通过、密钥已钉扎 |
| VERIFIED→EVALUATED | 评测报告 | `rule_id` | 报告含规则版本/引擎版本 |
| EVALUATED→AUTHORIZATION_PENDING | 评测 + 身份 | — | 二者均有效 |
| AUTHORIZATION_PENDING→AUTHORIZED | 授权决定 | — | **subject / scope / expires_at 三字段必填** |
| AUTHORIZED→MONITORED | 监测通道 | — | — |

### 1.3 五条禁止边（机器拒绝，已实测）

| 禁止边 | 拒绝理由（运行时返回） |
|---|---|
| 评分 96 → AUTHORIZED | `score cannot grant authorization (Evaluation != Authorization)` |
| `EVALUATED → AUTHORIZED` | 缺 authorization 三字段 → `authorization requires subject/scope/expires_at` |
| `REVOKED → 任意`（除自身） | `terminal state REVOKED cannot transition to ...` |
| `VERIFIED → AUTHORIZED`（跳级） | `illegal transition` |
| 状态缺证据 | `AUTHORIZED requires evidence` |

实现：`proposals/p20_trust_lifecycle/lifecycle_model.py`（`transition()` 全 fail-closed）。

## 2. 交付物二：Revocation & Expiration Specification

### 2.1 四类撤销

| 类型 | 含义 | 典型触发 | 下游影响 |
|---|---|---|---|
| **EVIDENCE** | 证据失效（哈希变、签名无效、来源变更） | 原文改动、解析器升级后重算不一致 | 该证据支撑的评测 → 授权 |
| **IDENTITY** | 身份撤销（密钥泄露、主体冒用） | 钉扎密钥移除、撤销列表更新 | 该主体所有授权 |
| **AUTHORIZATION** | 授权撤销（范围超限、期限到、事故） | 事故登记、策略变更 | 运行中的部署 |
| **VERSION** | 版本撤销（有缺陷的引擎/规则） | CVE、规则重大变更 | 用该版本产出的所有证据 |

### 2.2 记录字段

```
rev_id / kind / target / reason / at / scope / recover_condition / propagates_to
```

`recover_condition` 默认 `re-register + re-evaluate`——**撤销不可逆**，只能重新走链路。

### 2.3 传播：级联，不靠人工

实测（`A6-revoked-evidence` / `A6-cascade-auth`）：
```
撤销 ev-1（EVIDENCE）→ eval-1（依赖）→ auth-1（下游授权）
is_revoked("auth-1") == True  ⇒ 旧授权不得再被当作有效
```
**验收对照**：任务书要求"下游能识别失效、不能继续用旧授权"——本地原型已满足；**产品侧尚未实现**（`certificates.md` 里 CRL 仍是 v0.2 目标，FACT）。

### 2.4 过期 ≠ 撤销（必须分开）

| 维度 | 过期 EXPIRED | 撤销 REVOKED |
|---|---|---|
| 原因 | 时间到 | 事件触发 |
| 可恢复 | 经 RE-EVALUATED 可回 AUTHORIZED | **不可恢复**，只能重新登记 |
| 下游语义 | 需复评 | 立即失效 |

允许 `EXPIRED → AUTHORIZED` 必须经由复评；`REVOKED → AUTHORIZED` **在任何路径下都不允许**。

## 6. 交付物六：Commercial Assurance Boundary

| 输出 | 是什么 | 不是什么 | 责任边界 | 必须附 |
|---|---|---|---|---|
| **Registry 登记记录** | 主体已登记这一事实 | 不代表安全认证 | 登记不代表合格 | 登记时间、登记人、scope |
| **Evidence 证据记录** | 某时某条件下采集的证据 | 不代表事实绝对真实 | 只对采集范围负责 | 来源、哈希、采集环境 |
| **Evaluation 评测报告** | 按公开方法的技术评估 | 不代表零风险 | 方法公开、结果可复算 | 规则版本、引擎版本、语料版本 |
| **Authorization 授权决定** | 明确主体/范围/期限/条件的许可 | 不等于永久信任 | 越界即失效 | 四要素齐全 |
| **Monitoring 监测** | 持续观测 | 不代表持续安全保证 | 只报观测到的事实 | 采样频率、覆盖范围 |

**六条原则逐条落地**：Registration≠Verification、Verification≠Evaluation、Evaluation≠Authorization、Authorization≠Permanent Trust、CI Green≠Security Assurance、Self-evaluation≠Independent Certification。
