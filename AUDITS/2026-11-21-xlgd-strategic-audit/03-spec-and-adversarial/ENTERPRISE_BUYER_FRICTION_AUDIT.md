# ENTERPRISE_BUYER_FRICTION_AUDIT（企业采购阻力审计 · 2026-11-21）

> 出发点：**不要假设企业需要一个治理平台。** 企业只为"一个具体问题 + 一个能背锅的结论"付钱。
> 本文件逐条回答指令 §24 的 14 个问题，并给出一个可卖的最小产品（不设价格）。

## 一、14 个采购问题 × 当前答案

| # | 企业会问 | 当前能回答吗 | 事实依据 |
|---|---|---|---|

## 二、企业真正会卡住的三处（按致命度）

1. **责任归属**（#2）：结论出错谁赔？没有主体 → 大企业法务直接否决。
2. **审计留痕不可作证**（#5）：安全团队一看日志无链、失败被吞，就不会采用。
3. **版本冻结**（#6）：合规场景要求"这一版证据对应这一版对象"，当前无法证明。

> 这三处不是"功能缺失"，是**交易前置条件**。补齐前，任何"企业级"表述都不成立。

## 三、六个候选痛点 × 付费可能性（诚实评估）

| 痛点 | 需求真实性 | 我们能交付吗 | 结论 |
|---|---|---|---|
| **采购前 Agent 风险评估** | 高（企业采购流程真实存在） | 弱（评分不可信，G2 100/A+） | 暂不可卖 |
| **MCP 工具权限审计** | 中高（MCP 普及中，权限是硬问题） | **可**（Synomos `gov_scan` 实测命中手机号/邮箱/本地路径，V） | **可试点** |
| **Agent Skills 安全审计** | 中（平台侧有需求） | 不可（P0-1/2/3 未修） | 等修复 |
| **上线前治理检查** | 中 | 部分（lgd-engine 变更判定可跑） | 可绑项目卖 |
| **Evidence Package（证据包）** | 中（审计/取证） | **可**（唯一实测通过的链路） | **可卖** |
| **CI/CD Agent Gate** | 中 | 部分（`lgd-gate` 原型） | 可做免费引流 |

## 四、建议的最小可销售单元（一个，不是平台）

**"MCP 工具权限审计 + 证据包"按次交付**
- 输入：客户的 MCP 服务器清单 / 一个 agent 的证据包；
- 输出：`gov_scan` 结果 + 证据包校验结果 + 一页结论（含"能验/不能验"）；
- 交付时间：单次 1–2 天（人工复核占大半）；
- 可重复销售：是（按对象计次）；
- **不承诺**：不做"安全认证"，不做 SLA，不做平台。

## 五、为什么不是"完整治理平台"

| 平台化路径 | 现实 |
|---|---|
| 需要 8–10 个模块（身份/注册/证据/评估/授权/监控/撤销/争议） | 后 4 个模块**零实现**（V） |
| 需要运维、SLA、多租户 | 单人维护，Bus Factor=1 |
| 需要客户先有预算 | 无任何询价证据 |
| 平台卖的是"集成"，我们卖的是"一个能背书的结论" | 先有结论可信度，才有平台 |

## 六、30 天内可验证的三件事

1. 找 1 家企业（医械线已有真实场景）问一句："你们采购 Agent 时，谁签字放行？"——记录真实流程（不改代码）。
2. 用 `gov_scan` 对 10 个公开 MCP 服务器做只读扫描，产出样张（看是否有价值感知）。
3. 把"能验/不能验"写进一页 PDF——**这是销售材料里最重要的一页，比功能列表重要**。
