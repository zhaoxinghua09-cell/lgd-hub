## P0-2 · LGD-Eval 授权语义

### 2.1 原始问题（铁证）

- **仓库和分支**：`LGD-Eval/lgd-gate` @ `main` `10b3a22`；消费侧 `LGD-Eval/LGD-Eval`、`LGD-Eval/skill-audit`
- **问题定位**：`action.yml:86-89`
  ```yaml
  if   [ "$SCORE" -ge 96 ]; then TIER="L0"; SUGGEST="免审批直接执行"
  elif [ "$SCORE" -ge 81 ]; then TIER="L1"; SUGGEST="一次性确认后执行（60 rpm）"
  elif [ "$SCORE" -ge 51 ]; then TIER="L2"; SUGGEST="人工复核后执行（30 rpm）"
  elif [ "$SCORE" -ge 31 ]; then TIER="L3"; SUGGEST="每次强制确认，建议先过沙箱"
  ```
  输出项声明为 `tier: Suggested execution tier (L0-L5)`。
  → **一个 0–100 的分数，直接产出"免审批直接执行"**。这就是任务书说的"评分直接授予执行权限的歧义"。
  另：`skillgate.py:10` 把 `exit 0` 定义为 `pass`，消费方极易把"进程退出码"读成"允许安装"。
- **实际修改文件**：本轮**未改仓**；给出可运行原型（见下）。
- **修改前后差异（建议）**：删除 `tier` 输出，改为两个彼此独立的输出：`evaluation`（分数/维度）与 `risk`（发现清单）；授权由独立签发器给出。

### 2.2 三权分离原型（可运行，已验证）

- **文件**：`proposals/p02_authorization/authorization.py` + `test_authorization.py`（stdlib-only，可直接搬进仓）
- **测试命令**：`cd proposals/p02_authorization && python test_authorization.py`
- **实际测试结果**：`Ran 10 tests … OK`（10/10）

| 用例 | 断言 | 结果 |
|---|---|---|
| 满分 100 + 未解决 CRITICAL | 必须 NOT_GRANTED | ✅ |
| 满分 100 但无策略 | 默认拒绝 | ✅ |
| 证据哈希缺失 | **UNKNOWN**（fail-closed） | ✅ |
| 评测不完整 | **INCOMPLETE**（fail-closed） | ✅ |
| 评测者自签 | NOT_GRANTED（职责分离） | ✅ |
| 全部满足 | GRANTED + scope + 决策哈希 | ✅ |
| 分数低于策略阈值 | NOT_GRANTED | ✅ |
| MEDIUM 发现 | 不阻断但记入 risk_band | ✅ |
| 已解决的 CRITICAL | 不阻断（支持整改后复评） | ✅ |
| 策略要求全部闭环 | NOT_GRANTED | ✅ |

- **语义边界（关键）**：`score` 只作为证据被记录，**不进入任何判定分支**；`GRANTED` 必须同时满足"证据可核验 + 评测完整 + 策略匹配 + 无阻断发现 + 签发者≠评测者"。
