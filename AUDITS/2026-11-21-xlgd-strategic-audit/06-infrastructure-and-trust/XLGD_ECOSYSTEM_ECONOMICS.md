# XLGD_ECOSYSTEM_ECONOMICS（生态经济模型 · 2026-11-21）

> 原则：**商业化不能人为破坏开放协议的互操作性。** 任何"只有付费才能验"的设计都是自杀。

## 一、两层结构

### Open Ecosystem（永久免费，不可设限）
| 项 | 理由 |
|---|---|
| 规范文本（含 MUST/SHOULD） | 不开放就无法独立实现 |
| 参考实现（CLI 核心） | 不开放就无法复现 |
| 测试向量 + 负向样本 | 不开放就无法验证 |
| 校验器（离线 kit） | **必须免费**，否则"验证"变成收费闸门 |
| 公共评测结果（含失败） | 不公开失败就没有可信度 |

**红线**：不得对"验证一个证据包"这件事收费——收的是"人做的审计与责任"，不是"密码学校验"。

### Commercial Layer（可售）
| 项 | 可售性 | 说明 |
|---|---|---|
| Enterprise Deployment（部署支持） | 高 | 客户环境适配、离线包、培训 |
| Advanced Evaluation（深度评测） | 中 | 需先修 P0，否则卖的是不确定 |
| Private Evidence Management（私有证据库） | 中 | 客户数据不出境 |
| Custom Governance Policies | 中 | 定制策略与审批流 |
| Continuous Monitoring | **高**（需求最真） | 需先建（40.6% 漂移数据支撑） |
| Professional Audit（专业审计） | **最高**（当前唯一可交付） | MCP 权限审计 + 证据包 |
| Support & Maintenance | 中 | 版本兼容与升级 |

## 二、六个问题逐条回答

**1. 哪些必须永久免费？** 规范、参考实现、向量、校验器、公共结果。
**2. 哪些适合商业化？** 专业审计（人工）、持续监控（订阅）、私有证据管理、企业部署。
**3. 哪些需要企业版？** 私有证据库、多租户、审计日志留存、SLA（目前无能力提供 SLA）。
**4. 哪些适合专业服务？** 审计、培训、迁移、复测。
**5. 哪些可形成订阅？** 监控 + 版本变更重评（需先有实现）。
**6. 哪些不能靠收费形成优势？** 校验器、规则清单、评分——收了钱只会让人去找免费的替代。

## 三、开放与商业的接口（三条硬规则）

1. **免费层必须能独立完成"验证"**（否则生态不可信）；
2. **付费层卖的是"人的判断 + 责任 + 持续"**；
3. **付费不得改变规则**——客户不能买到"更宽松的规则"。

## 四、收入结构（12 个月设想，全部为 I）

| 来源 | 占比设想 | 前置条件 |
|---|---|---|
| 按次审计（MCP/证据包） | 60% | 1 个客户 + 模板 |
| 复测/持续监控 | 25% | monitoring 实现 |
| 企业部署/培训 | 10% | 有客户要求 |
| 咨询机构分成 | 5% | 1 个伙伴 |

## 五、不能做的事（明确）

- 不卖"通过"、不卖"认证"、不卖"评级"；
- 不做"付费优先出现在 Registry"（会毁掉 Registry 中立性）；
- 不做"闭源规则"（规则必须公开，否则无法被独立实现）。

## 六、验收判据

1. 断网、不付费的人也能完整验证一个证据包（当前 ✅）；
2. 付费客户拿到的规则与免费版**完全一致**；
3. 公开结果包含失败案例（当前有，但外部 0）；
4. 无任何"付费才能通过"的设计。

> 诚实条款：收入结构为判断（I）；当前收入 0，唯一可交付的付费项是"专业审计"。
