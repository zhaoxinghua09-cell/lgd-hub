### 3. 计划修改（未应用）
新增 `proposals/p13_anchor_registry/anchor_registry.py` + `sample_registry.json`（由真实记录归一化生成）+ `test_anchor_registry.py`。

核心：**display claim 由成分推导，禁止手写**。

```python
REQUIRED_COMPONENTS = {
  "ots":    ("bitcoin_block_header", "merkle_path"),
  "rekor":  ("entry_signature", "checkpoint_signature", "inclusion_proof"),   # 三者分开记
  "rfc3161":("tsa_signature", "tsa_chain"),
}
compute_claim(rec) -> anchored | partial | timestamp_pending | failed | unanchored
```

规则（对应任务书第 4、5 条）：
- OTS `calendar_status ∈ {pending, "", unconfirmed}` → 只能 `timestamp_pending`，出现 `bitcoin_anchored` 即 `E_OTS_PENDING`；
- Rekor `inclusion_proof is not True` → 最多 `partial`，出现 `anchored` 即 `E_REKOR_INCLUSION`；
- 验证失败且 `reason` 为空 → `E_SILENT_FAIL`（正是 freetsa 那条）；
- proof 文件 sha256 与记录不符 → `E_PROOF_DIGEST`（真算，不是抄）。

### 4. 测试（正向 / 负向 / 边界）
命令：`python proposals/p13_anchor_registry/test_anchor_registry.py`
实际：**12 passed / 0 failed，exit 0**

- 正向：rekor 三成分全验证 → `anchored`；rfc3161 全验证 → `anchored`；OTS 已进区块 → `bitcoin_anchored`
- 负向：inclusion 未验证 → `failed`；验证失败但原因为空 → `E_SILENT_FAIL`；缺 proof → `E_PROOF` + claim 降 `partial`；未知锚型 → `E_TYPE`
- 边界：**OTS pending 只能是 `timestamp_pending`**（本条就是任务书第 4 条的机器化）

真实 registry 校验：`records 4 → claims {failed: 3, timestamp_pending: 1}，ok = false`。**四条真实记录没有一条被允许声称 anchored**，与仓库现状一致，说明结构没在替它们吹牛。
