# XLGD_IP_AND_LICENSING_AUDIT（IP、许可与商业边界审计 · 2026-11-21）

> 约束：**只提风险与建议，不改变任何许可、署名、商标或商业授权。**
> 结论：**许可证是本生态"最便宜、也最致命"的问题**——它的修复成本几乎为零（加一个文件），但它的后果是"企业法务一票否决"。

**一句话**：53 个仓（38 + 15）在法律上处于"别人不能用"的状态。

## 二、逐仓点查（5 个核心仓，V）

| 仓 | LICENSE 文件 | 仓库元数据 | package/pyproject | README 口径 | 判定 |
|---|---|---|---|---|---|
| `uibc-core` | Apache License 2.0 | Apache-2.0 | — | — | **一致** |

| `synomosai-governance-mcp` | MIT | MIT | MIT | — | 一致 |
| `LGD-Eval` | **CC BY 4.0（"Attribution 4.0 International"）** | MIT | package.json **MIT** / pyproject **MIT** | README 提 Apache-2.0 | **三方冲突（V）** |
| `silent-failure-catalog` | **无 LICENSE 文件（克隆内）** | NOASSERTION | — | — | **缺失（V）** |

另：`uibc-core` 的仓库描述自带混合口径——"代码 Apache-2.0；**理论文本保留所有权利**"。这在法律上意味着：**引用代码可以，引用理论不可以**（除非法务另有解释）。这条必须显式化，否则 README 的"开放"印象与许可事实不符。

## 三、八类风险清单

## 四、专利与 AI 生成内容（两个敏感项）

- **专利**：Apache-2.0 自带专利授权条款（对使用者有利）；但若未来要申请专利，**已公开的部分可能丧失新颖性**。建议在商业化前做一次 FTO（自由实施）评估，特别是"证据包结构 + 可撤销生命周期"这类可能被大厂布局的方向。
- **AI 生成内容**：本生态大量文本由 AI 辅助生成；多数司法辖区对 AI 生成物**不给予著作权**。建议：核心理论文本做"人类实质性修改"留痕（版本+说明），否则"保留所有权利"在法律上可能无所附着。

## 五、必须由本人决定的三件事（不可代为决定）

1. **LGD-Eval 定哪个许可**（CC BY 4.0 / MIT / Apache-2.0）——影响全部下游；
2. **理论文本是否允许商业引用**（当前"保留所有权利"实际上阻断了引用）；
3. **主名称统一为哪一个**（XLGD / LGD / UIBC 三者的关系需要一句话定义）。
