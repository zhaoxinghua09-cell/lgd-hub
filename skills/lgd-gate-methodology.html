What it is / 是什么

LGD gate methodology: a from-zero playbook for building open-source trust and safety tooling with registration, evidence, and gating built in. Use it to plan version cadence, seven-layer testing, quality gates, and false-positive targets.

从 0 到 1 做开源信任/安全工具的完整方法论（LGD 三律：有籍、有证、有门禁）。当你要新建一个开源扫描器、评测器或门禁工具，要规划版本迭代节奏、七层测试、质量门禁与误报率目标，或要把自己的理论/框架工程化成可复用工具时使用。

When to use it / 什么时候用它

  • 要从零做一个开源信任或安全工具时
  • 要规划版本节奏与七层测试时
  • 要设定误报率目标与发布门禁时
  • 要把一套理论工程化成可复用的工具时

通用开源项目模板与清单（awesome / best-practices 类）多为条目式清单：写 README、加测试、配 CI、发版本。覆盖面广，但不给"按什么判据算过"。
  • 三律是可判的，不是口号 —— 有籍（每版有档可追）/ 有证（每个结论有实跑）/ 有门禁（关键节点有检查）——每条都落到一件具体产物与一条具体命令上，能被第三方复算。
  • 给出误报率与豁免的操作口径 —— 怎么把"误报"变成一条可复核记录、怎么让门禁在 CI 里阻断，是本件与清单类文档的主要差别。
  • 自曝适用边界 —— 不适用于纯前端/纯 UI 项目；也明说不构成合规结论、不替代评分机构。

Where they win / 对方强在哪 —— 通用性。清单类文档适用于任何项目；本件只对"要建一个可被外部复算的信任/安全工具"这类目标有效。
