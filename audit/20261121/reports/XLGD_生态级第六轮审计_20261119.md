### A.2 三处结构性断裂

**断裂一：许可证不是一套**
Apache-2.0（uibc-core / skill-audit / lgd-engine / medxpert）+ MIT（LGD-Eval / lgd-gate / synomosai）+ **ARR**（lgd-hub）。ARR 那一份直接把"生态可复用"这句话否掉——别人不能合法拿走 hub 的内容去做自己的实现。

**断裂二：版权主体三种写法**
`Copyright (c) 2026 SynomosAI / LGD Ecosystem`（LGD-Eval）、`Copyright (c) 2026 LGD-Eval`（lgd-gate）、`Copyright (c) 2026 SynomosAI`（synomosai-mcp）。同一批代码，三个权利人署名 → 出事时谁主张、谁授权，无法回答（`INFERENCE`，但署名是 `FACT`）。

**断裂三：入站授权没定义**
`uibc-core/CONTRIBUTING.md` 无 `Signed-off-by`（DCO）、无 CLA 文本；`lgd-gate/CONTRIBUTING.md` 连 license grant 条款都没有（`FACT`，grep 无命中）。出站是 Apache/MIT，入站却没说"你提交即授权"→ 外部 PR 合并进来会有权利瑕疵。

## B. 跨项目状态模型

### B.1 现状：三套词汇，互不翻译

| 维度 | uibc-core | lgd-gate | medxpert | SynomosAI MCP |
|---|---|---|---|---|
| 身份 | `identity.json`（自述 agent_id/owner） | 无 | 无 | 无 |
| 证据 | `evidence_root` + S1–S12 检查 | 无 | 摘要 + freshness | 无 |
| 评测 | `trust_level`（unanchored/attested） | `Trust Score 0-100` + `tier L0-L5` | 无 | 无 |
| 授权 | **不存在** | **由分数推导**（`SCORE≥96→L0 免审批`） | 无 | 无 |
| 撤销 | 文档骨架 | 无 | 无 | 无 |
| 时效 | 无 | 无 | `as_of/freshness/next_review/overdue` | 无 |

`FACT`：uibc_core 全库 `NOT_GRANTED` 零命中；`lgd-gate/action.yml:86` 有 `TIER="L0"; SUGGEST="免审批直接执行"`。

### B.2 建议的统一模型（七维，机器可读）

```json
{
  "subject_id": "uibc:agent:<uuid>",
  "identity":     {"state": "self_asserted|bound|verified|revoked", "evidence_ref": "...", "bound_to": null},
  "evidence":     {"state": "none|present|reproducible|attested", "root": "sha256:...", "checks": {"S11": "PASS"}},
  "evaluation":   {"state": "not_run|pass|fail|unknown|incomplete", "score": 61, "engine": "lgd-gate@1.1.0", "manifest_ref": "..."},
  "authorization":{"state": "NOT_GRANTED|GRANTED|SUSPENDED", "scope": [], "granted_by": null, "decision_ref": null},
  "revocation":   {"state": "active|revoked", "reason": null, "revoked_at": null, "propagated_to": []},
  "freshness":    {"state": "ok|aging|stale|unknown", "as_of": "...", "overdue": true},
  "adoption":     {"state": "self|external_corpus|independent_impl|third_party_run", "external_evidence": []}
}
```

**四条不变式（必须写进 schema 校验器）**
1. `evaluation.state == "pass"` **不得**推出 `authorization.state == "GRANTED"`（缺 `authorization` 块一律按 `NOT_GRANTED`）。
2. 任一维度为 `unknown`/`incomplete` → 整体取 `unknown`，并 fail-closed（拒绝执行、拒绝签发）。
3. `revocation.state == "revoked"` **支配**其余六维：无论 evaluation 多高、evidence 多全，一律 `NOT_GRANTED`。
4. `freshness.overdue == true` 时，`evaluation` 必须重新跑过才允许 `pass`（否则标 `stale_evaluation`）。

**现状符合度**：不变式 1 违反（lgd-gate 直接映射）；2 部分（uibc 有 INCONCLUSIVE，但 lgd-gate `exit 0=pass`）；3 无实现；4 无实现。

## E. Trust Registry 可行性报告

### E.1 定位与职责边界

Registry **只做三件事**：登记（谁、什么东西、什么状态）、撤销（谁失效了）、查询（这个 subject 现在能不能用）。
**不做**：评测（属 lgd-gate）、验证（属 uibc verify）、检索（属 medxpert）。避免把"登记"做成第二个真相源。

| 现有模块 | 职责 | 交给 Registry 的部分 |
|---|---|---|
| uibc-core verify | 验包、算 evidence_root | 只上传 `evidence.state` 与 `root` |
| lgd-gate | 打分、出报告 | 只上传 `evaluation.state/score/manifest_ref` |
| medxpert | 时效与来源 | 只上传 `freshness.state` |
| Registry | 汇总七维 + 撤销传播 + 查询 | — |

### E.2 数据模型（append-only）

```
entry = {
  seq, subject_id, kind(identity|evidence|evaluation|authorization|revocation|freshness),
  state, payload_digest, prev_entry_hash, entry_hash,
  signer_keyid, signature, created_at
}
```
- 只追加，不修改；撤销 = 新增一条 `kind=revocation, state=revoked` 的条目。
- 每条 `entry_hash = sha256(canonical(entry 去 signature))`，链式 `prev_entry_hash` → 可复算、可对账。
- 查询"当前状态"= 从尾部回溯该 subject 各 kind 的最新条目（**撤销优先**）。

### E.3 API 草案（REST，只读为主）

```
GET  /v1/subjects/{subject_id}                  → 七维当前状态
GET  /v1/subjects/{subject_id}/history?kind=     → 条目流（可复算）
POST /v1/entries                                 → 追加一条（需签名 + 授权 token）
POST /v1/revocations                             → 撤销（需双签：登记方 + 复核方）
GET  /v1/health                                   → 链高、最后一条 hash、签名者
```

### E.4 威胁模型

| 威胁 | 后果 | 缓解 |
|---|---|---|
| Registry 私钥泄露 | 攻击者可伪造 GRANTED | 双签 + 密钥分持；撤销条目必须两人签 |
| 条目被删改 | 历史被改写 | append-only + 外部锚（OTS/Rekor 已有通道） |
| 重放旧状态 | 用"已被撤销前的状态"骗过下游 | 下游校验 `seq` 单调 + `revoked` 支配 |
| 拒绝服务（查询放大） | 不可用 | 只读副本 + 限流；缓存链高 |
| 虚假主体抢先登记 | 冒名 | `subject_id` 由公钥派生，不允许自定义字符串 |

### E.5 成本估算（首年，人民币量级）

| 项 | 估算 |
|---|---|
| 服务（1 台 2C4G + 对象存储 + CDN） | 0.6–1.2 万 |
| 域名/证书/监控 | 0.2 万 |
| 开发（复用现有 schema，约 6 人周） | 内部工时 |
| 外部锚（OTS 免费 / RFC3161 约 0.1–0.3 元/次，按 10 万次） | 1–3 万 |
| 审计与合规咨询（若对外承诺） | 视范围 |

**结论：技术上可行，成本可控，但只有在"有第二个独立实现者"之后才值得上线**——否则它只是给一个单人生态增加运维负担。
