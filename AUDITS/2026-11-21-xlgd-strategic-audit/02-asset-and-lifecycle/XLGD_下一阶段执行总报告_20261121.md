## 12 · 三个核心问题（逐条回答）

### A. 从"有一套工具"到"被外部采用的信任基础设施"，最缺的是什么？
**VERIFIED 事实层**：外部贡献者 0、外部独立验证 0、外部引用 1（且是分歧）、付费客户 0、标准采纳 0。
**判断（INFERENCE，高置信）**：缺的是**可被第三方独立复现并签名的结论**，以及**让第三方敢用的法律许可**。功能层面 1–5 段已经够用；真正的断点在"别人能不能验、敢不敢用、愿不愿签"。
**推论**：所以下一阶段的重心不是加功能，而是把"结论"变成一种**可携带、可签名、会过期、可撤销**的物件。

### B. 哪些环节最容易被误判为"已经完成"？
| 易误判 | 事实 | 反证 |
|---|---|---|
| CI 全绿=安全 | 1015 测试全绿 | CI 只证明不崩，不证明能拦 |
| 自评 100/A+=通过 | benchmarks 页写 0 findings/100A+ | 同 HEAD 实测 86/A、10 findings |
| 多账号=独立 | 4 账号全同一人 | 外部贡献者 0 |
| 参加 ITU/W3C/IETF=标准采纳 | 有帖/有 TD 稿 | 无提交记录、无回复、无采纳 |
| 注册表有条目=背书 | 3 条硬编码示例 | 无外部登记、无背书 |
| 证据完整=证据为真 | inclusion/consistency 实测通过 | SPEC 自己写明完整性≠真实性 |
| PyPI 有下载=有用户 | 120 次/日 | 无 issue、无 PR、无引用 |

### C. 如果我是外部审查者，会先攻击哪里？
按"能当场复现"排序（全部已复现，附证据文件）：
1. **凭证外发样本 89/A exit 0、skillgate 100/A+**（`C_bench.md`）；
2. **写 `~/.ssh` 样本 skillgate 100/A+ / 0 findings**（正则 `~\.ssh/` 不匹配 `~/.ssh/`）；
3. **缺 `cryptography` 仍 `verified=true` exit 0**（`repro_no_crypto.py`）；
4. **空目录 67/C exit 0，且过 `--fail-under 60`**（`B_dynamic.md`）；
5. **4 个包装入口 `ValueError`**；
6. **LICENSE 三方冲突（CC BY 4.0 / MIT / Apache-2.0）**；
7. **自评数字与实测不一致（100/A+ vs 86/A）**；
8. **interop matrix 三对端全 not tested**。
**我们的补法**：1–4 用 P0-1/2/3 修，5 用 P1-1，6 用 P1-2，7 用一次"数字统一"提交，8 用 P1-3 的签名机制让外部替我们测。
