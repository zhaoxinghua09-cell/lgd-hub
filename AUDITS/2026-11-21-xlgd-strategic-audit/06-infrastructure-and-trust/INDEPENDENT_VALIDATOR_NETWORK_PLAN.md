# INDEPENDENT_VALIDATOR_NETWORK_PLAN（外部验证者网络建设 · 2026-11-21）

> 目标：不是"邀请几个朋友测一下"，而是**一个可长期运转、允许分歧、不能被钱影响的结构**。
> 现状（V）：验证者 0、结果签名 0、外部实现 0；唯一可用的通道是 `validator-kit-20261121.zip`（6/6 自测）。

## 一、五类角色 × 任务与门槛

| 角色 | 任务 | 门槛 | 产出 | 独立性要求 |
|---|---|---|---|---|
| Independent Implementer | 仅凭规范写第二实现 | 能读规范 | 兼容性报告 | 与作者无雇佣/合作 |
| Independent Evaluator | 对某对象出评测结论 | 会跑评测器 | 带签名的评测结果 | COI 披露 |
| Security Researcher | 找漏洞/绕过 | 有 PoC | 漏洞报告（CVD） | 可匿名 |
| Compatibility Tester | 跨平台复跑 | 有第二环境 | 环境记录 + 结果 | 无要求（但不计入"独立"） |
| Enterprise Validator | 在企业环境验证 | 企业授权 | 受控结论（不外发） | 与作者无商业依赖 |

## 二、八个机制（逐条对照）

| # | 机制 | 设计 | 现状 |
|---|---|---|---|
| 1 | 公开验证任务 | 一页任务清单（跑 kit / 写实现 / 复跑向量） | 待建 |
| 2 | 可复现样本 | 固定 SHA + `SHA256SUMS` | **有（V）** |
| 3 | 允许负面结果 | 明示"发 FAIL 也是成果" | **有（kit README）** |
| 4 | 记录身份与利益关系 | `identity` + `coi` 三字段 | 设计有，实现无 |
| 5 | 保留原始结果 | append-only，不覆盖 | 无 |
| 6 | 允许复核 | 任何人可重跑命令 | **有** |
| 7 | 支持多实现 | 兼容矩阵多列 | 无 |
| 8 | 允许不同意见并存 | `dispute` 挂原结论旁 | 无 |

## 三、防污染的五条红线（指令明确要求）

1. **不得支付报酬影响结论**（可报销差旅，不得按结论付费）；
2. **不得用贡献积分换 PASS**；
3. **不得用商业合作绑定验证结论**（合同写"不影响"）；
4. **不得由作者代写验证报告**（可提供模板，不可代填）；
5. **不得把"作者的另一个账号"计为独立验证者**。

## 四、激励设计（不用钱，用可见度）

| 激励 | 成本 | 对验证者价值 |
|---|---|---|
| 结果署名 + 公钥身份 | 低 | 可积累个人信誉 |
| "首个外部验证"记录 | 低 | 稀缺 |
| 被引用（报告/文档） | 低 | 学术/职业价值 |
| 失败案例署名（若其发现） | 低 | 研究者声誉 |
| 免费获得企业审计报告样例 | 低 | 实用 |

## 五、90 天路线（三步，每步可停）

| 阶段 | 动作 | 判据 |
|---|---|---|
| S1（Day 1–30） | 发 1 份邀请（三选一）+ 签名工具 | 1 条外部签名（含 FAIL） |
| S2（Day 31–60） | 公布"验证者名单"页（可匿名）+ 第一个外部任务清单 | 名单 ≥1 非作者 |
| S3（Day 61–90） | 开放"提交验证结果"入口（PR 模板 + 校验脚本） | 出现第 2 条外部结果 |

## 六、验收判据（网络是否成立）

1. ≥2 个**不同主体**的验证结果；
2. 至少 1 条是 **FAILED/INCONCLUSIVE**（证明允许负面）；
3. 每条可离线复算；
4. 无一条因付费而改变结论（可审计的 COI 记录）。

> 诚实条款：全部机制除"样本可复现""允许负面"外均未落地；本文件是"如何开始"，不是"已建成"。
